# 七分钟答辩

主讲材料为[答辩介绍.pptx](答辩介绍.pptx)，共9页。按“目标 → 观察 → 流程 → 具体决策 → 结构 → 结果与边界”讲解，总时长约7分钟。

| 页码 | 时间 | 本页要讲清的一句话 |
| --- | ---: | --- |
| 1. 目标与边界 | 25秒 | 最小化完整Trace的时间与调用成本，前台决定怎样搬，后台决定是否缓存。 |
| 2. 三个关键观察 | 55秒 | 合并、并发与缓存都存在相反作用，所以不能只靠固定规则。用两个小例子说明合并不一定更快。 |
| 3. 总体流程 | 40秒 | 两个回调串起在线决策：未命中到达时规划，完成后判断缓存；engine负责执行。 |
| 4. 整理与分块 | 50秒 | 请求有效范围与物理补读不同；以100B起点、1MiB池说明每块怎样合法放下。 |
| 5. 联合DP | 65秒 | DP同时选边界和路径；计数DP在适用条件与预算内比较组数，估价不等于最终J。 |
| 6. PROMOTE准入 | 55秒 | 复用新鲜、净收益为正、投入有预算才缓存；满池可替换，当前没有主动延期。 |
| 7. 关键数据结构 | 40秒 | IovIndex/Piece管映射，DP管组合，Work管本次成本，History和在途记录管复用。 |
| 8. 性能与原因 | 55秒 | 公开集自动分88.4555；通过费用与读量解释收益，同时承认策略回调计算增加。 |
| 9. 边界与交付 | 35秒 | 验证合法不代表每例更优；明确扩展退化和极端内存，再指出完整复现入口。 |

主讲不逐行读公式；详细估价、缓存预算、计数DP条件与复杂度放在[算法设计](../04_算法设计与复杂度/算法设计.md)，完整数据放在[报告](../06_性能与资源报告/验证报告.md)。

## 可选现场演示（另计2—3分钟）

在材料根目录执行：

```bash
python3 05_自动化测试与复现/verify_submission.py
python3 run.py solve --prebuilt --input 04_算法设计与复杂度/示例/相邻对齐小读输入.json --result aligned.json
python3 run.py solve --prebuilt --input 04_算法设计与复杂度/示例/相邻非对齐读取输入.json --result unaligned.json
```

两例分别展示“合并DIRECT，J=6”与“分别AGGREGATE，J=48”。若有额外时间，`python3 run.py demo`运行七类场景的贪心/方案对照，双方均经官方回放。观察J及调用费、Trace时间与实际命中，不单看命中率。

## 问答定位

| 评委可能追问 | 对应材料 |
| --- | --- |
| 是否使用未来信息、内部模拟或特定case分支 | 算法设计第一节；`run.py quick`中的策略依赖检查 |
| cnt为什么不一定是真并发 | 算法设计2.3节的启动检查、复制估计与局限 |
| PROMOTE公式中的预算、卡占比和TTL | 算法设计第三节及附录B |
| 是否任何输入都比贪心好 | 报告第一节的扩展成本与退化；附逐例CSV |
| 调度开销、复杂度和大输入内存 | 算法设计附录A；报告第三、四节 |
