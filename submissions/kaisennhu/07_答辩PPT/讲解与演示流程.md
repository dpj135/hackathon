# 答辩讲解与现场演示

主讲材料为[答辩介绍.pptx](答辩介绍.pptx)，共9页。按“目标与观察 → 前台分块和DP → 后台PROMOTE → 数据结构 → 结果与边界”展开。前台连续三页，后台单独一页，避免在两个决策流程之间来回跳转。

| 页码 | 主题 | 讲解重点 |
| --- | --- | --- |
| 1 | 目标与边界 | J衡量完整Trace历时与调用费；策略生成计划，框架执行和计费。 |
| 2 | 三个关键观察 | 合并可能损失并发，路径使用不同资源，缓存命中仍有搬运成本。 |
| 3 | 前台流程 | 映射 → 分块 → DP → 依赖；用三个512B请求合并为一次DIRECT读解释结果。 |
| 4 | 前台分块 | 100B起点、3MiB请求、1MiB临时池；有效字节和物理补读分别处理。 |
| 5 | 前台DP | 联合选组边界与路径；空闲且预算允许时，计数DP补充比较组数。 |
| 6 | 后台PROMOTE | 本次读取已经成功，后续缓存投入需通过去重、复用、净收益和预算检查。 |
| 7 | 数据结构 | IovIndex/Piece管映射，DP管计划，Work连接实际计划与后台收益，History管复用。 |
| 8 | 性能结果 | 公开自动分与代表输入成本分解；同时说明策略回调的额外开销。 |
| 9 | 验证与边界 | 展示验证覆盖，保留扩展退化、估价局限和极端碎片内存边界。 |

## 流程动画

第3页和第6页使用原生PPT淡入动画，每页五次点击，按讲解顺序展开。进入放映模式后，用鼠标单击或方向键推进；图形与文字可在PowerPoint中编辑。

- 第3页：依次显示目标映射、合法片段、DP选路、传输依赖，最后显示三份请求合成一次读取的例子。
- 第6页：依次显示四道准入判断，最后显示“提升完成入池 → 未来同键请求命中”的流程。任何一道未通过都不提升，本次读取依然成功。

普通编辑视图及静态导出保留完整流程。页面与备注不包含个人署名或演讲时长；页码为右下角小字。字体使用微软雅黑（Microsoft YaHei），非Windows环境可能使用系统中文字体替代。

## 现场演示

在材料根目录执行：

```bash
python3 run.py demo
```

该入口准备依赖和输入，然后调用`demo.py`运行七个场景。它是命令行演示：对比官方贪心和本方案的J、路径、提升、命中与驱逐，并对双方输出做官方回放。输出保存在`运行结果/`。

若只讲解两个最小例子，可执行：

```bash
python3 run.py solve --prebuilt --input 04_算法设计与复杂度/示例/相邻对齐小读输入.json --result aligned.json
python3 run.py solve --prebuilt --input 04_算法设计与复杂度/示例/相邻非对齐读取输入.json --result unaligned.json
```

两例分别展示“合并DIRECT，J=6”与“分别AGGREGATE，J=48”。观察J及调用费、Trace时间和实际命中，不单看命中率。
