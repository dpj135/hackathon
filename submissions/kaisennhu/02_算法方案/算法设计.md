# 在线区间调度、观察窗口比较与缓存准入

## 目标与信息边界

最小化完整 Trace 的 J = time_cost_per_us × TraceTime + CPUCost + NPUCost。输入由主办方 SDK 的 on_submit 和 on_iocb_complete 回调提供。策略只使用当前未命中请求、运行状态及历史；不访问文件名、instance_id、随机种子、完整 Trace 或未来请求。

本实现是单一 C++17 策略。主办方模拟器负责真实的共享带宽、传输阶段、资源分配、TTL/LRU 和完成事件。算法不自行宣称完成时间。

## 前台规划

对每个 IOCB 建立 iov 累计结束位置索引。切分逻辑区间时二分定位首个相交 iov，只输出实际交集；首尾 SSD 扩读按 512B 对齐，禁止写入无关 HBM。

候选块上限取 2MiB 和 8MiB，均受实际临时池容量约束；比较候选成本后选择，而不是为某个长度固定路径。较大的可行块可以避免小尾块和额外调用，较小块则保留流水与池复用机会。无法进入候选模拟预算的输入使用 2MiB 规划及容量切分。

按设备和 SSD 起点排序，在同卡相接或重叠区间上做窗口为 128 的动态规划，联合选择合并边界和 DIRECT / AGGREGATE / FALLBACK。DIRECT 要求每个逻辑交集的 SSD 起点、HBM 目标和长度均符合对齐。暂存路径检查缓冲容量；DIRECT / AGGREGATE 检查所有者数与 IOCB 槽位约束。

拆分的 IOCB 不与其他所有者共享一个操作，避免不同操作交叉占用槽位后互相等待。输出显式的读→复制依赖；缓冲释放、复制并发和循环复用由 SDK 管理。

DP 使用资源工作量与调用成本的加法代理。SSD 为全局共享资源；复制活动按类型及设备分别估计，并按对应硬并发限制取值。DP 最优只针对当前代理和候选区间，不是对完整在线 J 的最优证明。

## 有界观察窗口比较

普通批次在不超过 1024 个可见请求、2048 个 iov、初始计划不超过 2048 个操作时，比较至多六种候选：两个块长下的 DP 方案，以及各自可行的 AGGREGATE / FALLBACK 路径偏好。DIRECT 保留直接路径；不满足目标池或槽位条件的操作保持原有合法路径。

历史窗口只保留仍含未完成前台请求的已到达批次，最多 32 批。按总 iov 32768 和基准计划操作预算 512 进一步截断。在窗口中对路径偏好进行反事实模拟，以观察批间槽位占用、缓冲池和共享带宽对流水的影响；仅执行当前批次选中的操作。

反事实模拟并不修改已经执行的任务。它使用官方 SDK 的同一资源模型，但省略窗口外工作、缓存命中搬运和后台提升，所以仍是条件性成本估计。不能将其称为真实全状态快照回放或已知未来的全局优化。

无历史前缀时，按完整操作形状和所有者映射缓存局部成本，最多保存 64 项，每项签名不超过 32768 个整数。缓存键不使用用例标识；只复用相同资源模型下、相同操作拓扑的结果。

在保守空闲、没有缓存及提升历史，且最多 6 个完整块、256 个 iov 时，还可枚举受限微批计划。单次枚举最多 3072 个候选；两个块长至多触发两次。该搜索只见当前 submit，且不将结论外推到有后台工作的状态。

## 最终计划与缓存账本

只对最终选定的前台操作记账：SSD 工作按物理字节，复制按有效字节，共享命令成本按有效字节分摊。全局 SSD 工作与单卡复制工作使用不同并行范围。保留该 IOCB 的边际工作估计，供完成回调使用；完成后释放账本。

每个缓存键维护跨时刻访问次数、EWMA 间隔及绝对偏差、最近需求、有复用证据的字节距离和提升预算。历史队列上限为 131072 条更新记录。相同到达时刻的重复不被当作独立周期复用证据。工作集压力只由跨时刻再次出现且可容纳的对象推进，一次性扫描不直接抹掉热点证据；这仍是对工作集的近似。间隔绝对偏差使新鲜度容忍观测到的到达抖动，稳定节奏下不会额外放宽。

## 缓存准入和来源选择

只有前台完整完成后才能发起提升。准入要求：至少两次有间隔的观测；整个对象不超过缓存池；间隔小于 TTL；最近需求没有超过 TTL，也没有超过估计访问间隔加两倍间隔绝对偏差；有复用证据的字节距离仍在容量范围内；没有相同键的缓存或在途提升。

每次未来命中的边际收益，估计为省去的前台读取、复制和调用，减去命中 H2D 的时间与调用。收益必须为正。

提升预算来自已观察到的同键读取工作量，按尚未记账的不同到达时刻累积，不用 TTL / 间隔外推固定数量的未来命中。实际缓存命中的完成反馈，可赚取不超过上次提升成本的后续预算。需求跨过容量或 TTL 边界时清除过时证据。预算本身来自代理估值，不是对实际总成本的竞争比保证。

PROMOTE_SSD 与 PROMOTE_HBM 的选择比较当前队列下预计就绪成本。HBM 提升的排队压力按真实源卡统计，复制并发按该卡 D2H 限制；SSD 提升计全局 SSD 压力。来源就绪估计可以包含等待，准入新增服务成本不把同一队列等待重复收费。

## 复杂度与资源边界

设 V 为总 iov 数、B 为块数、W=128、L 为最终映射交集数。索引构建 O(V)，排序 O(B log B)，区间候选至多 O(BW)，所有者集合维护带对数因子，映射约 O(B log Vmax + L)。通常生成两种块长的计划；高 iov 输入受预算保护，不进入普通候选模拟。

候选模拟的开销还取决于 SDK 中活动传输和完成事件数，不能把整个策略简写成 O(BW)。观察窗口、候选数、签名缓存和微批搜索均显式有界。完整进程仍包含 SDK 输入/输出 JSON、未完成请求和缓存状态，因此不是恒定内存算法。

## 通用性原则

带宽桶和固定调用成本来自公开规则，8 卡均衡是题面前提。对缓存过滤后的可见请求和运行队列，算法按实际设备与资源记账，不假定继续均衡。参数均为搜索预算、容量或规则导出的量，不按测试名称或精确资源组合切换特制策略。

本方法面向确定性赛题模型，不宣称对任意未来后缀全局最优，也不保证每个输入都优于贪心。验证报告完整列出较差输入、独立分布和资源开销。
