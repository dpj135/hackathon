# 构建与复现

完整克隆仓库后，在`submissions/kaisennhu`执行。环境为Linux或WSL，需C++17编译器、make、nm（binutils）、Python 3.10+；规模测试另用`/usr/bin/time`。基础运行不依赖第三方Python包、GPU或网络。

## 统一入口

| 命令 | 内容 |
| --- | --- |
| `python3 05_自动化测试与复现/verify_submission.py` | 核对全部提交文件、PPTX和二进制，独立回放四个示例 |
| `python3 run.py build` | 核验并复制仓库public中的固定SDK，编译唯一策略 |
| `python3 run.py solve --input input.json --result result.json` | 生成计划并由官方validator独立回放 |
| `python3 run.py quick` | 官方自测，以及38功能、74边界、19准入、6评分门禁、8engine检查，27项规划专项，以及策略目标文件依赖检查 |
| `python3 run.py score` | 官方39条，分别评方案与同计量入口的官方贪心 |
| `python3 run.py extended` | 553条输入，各3次运行、回放和输出哈希比较 |
| `python3 run.py compare` | 292条扩展输入，双方各3次成本对照 |
| `python3 run.py runtime` | 与官方贪心使用相同计量入口，39条各预热一次、正式测三次；分别记录策略时间、进程时间、堆内存和RSS |
| `python3 run.py scale` | 两类十万请求各一次；三类高iov各三次，记录策略耗时、堆内存、RSS |
| `python3 run.py demo` | 七个场景的贪心/方案对照及回放 |
| `python3 run.py all` | 执行以上完整验证，耗时较长 |

结果写入`运行结果/UTC时间`，可用`--output`指定。`--repeat`调整扩展及规划专项测试次数。辅助扩展对照超时600秒；官方评分仍使用原套件时限。score会拒绝非法结果、缺失输入、策略内存缺失/非法/超限或资源检查失败，不只看评分脚本退出码。

| official | 39 | 官方原始公开数据，不改字节 |

| admission | 19 | `admission_workloads.py` |

| planning_holdout | 24 | 已有组合，作为可见回归 |
| transfer_holdout | 24 | 既有组合，作为可见回归 |

`extended`和`compare`自动按manifest生成缺失的451条输入，并逐字节校验SHA256；63条固定输入保留在Git。高iov输入也由`stress_inputs.py`生成，无需保存大体积JSON。所有生成数据是本地合成负载，不是官方隐藏集。

## 加入新负载

```bash
python3 run.py build
python3 05_自动化测试与复现/independent.py --code 01_调度算法源代码 --output new_inputs --seeds 9401 9413 --submits 40 --per-card 32
python3 run.py extended --data new_inputs --repeat 3
python3 run.py compare --data new_inputs --repeat 3
```

先固定策略与SDK哈希，再生成未见负载。新种子未必代表新分布；扩大验证还应增加家族、资源组合、桶边界、到达变化和热点迁移。保留失败与成本回退，修改参数后重新留出未见数据。

## 结果口径

J是官方模拟成本，不是本机运行秒数。`policy_peak_mb`统计策略堆内存；`process_peak_mb`/RSS包含框架，单独报告。策略内部没有局部模拟；外部engine执行和validator不属于策略计算。

文档导出使用`生成方案报告.py`，另需python-docx；导出物供本地阅读，不进入Git。完整证据的源码哈希和逐例结果摘要位于06目录。

## 决策与资源开销测量

`python3 run.py runtime --repeat 3`分别编译策略和官方贪心，使用同一官方计量入口及`profile_main.cpp`回调计时器。固定同一可用CPU，每条公开输入预热一次，再交替运行三轮；每次都独立回放，并核对同一实现的输出一致性。对照策略可以产生不同合法计划，不要求两种策略输出相同。

`runtime/summary.json`保留环境、源码/engine/计时器/二进制哈希、编译耗时、预热数据、逐轮计时及输出哈希。计时口径：

- 回调时间只包括策略的on_submit与on_iocb_complete；最终取逐例中位数，汇总为中位数之和。
- 进程墙钟包含启动、框架执行和JSON读写，不包含预热、编译或独立validator；validator耗时单列。
- 策略堆峰值由官方计量入口统计；RSS由`/usr/bin/time`统计，包含框架与输出状态。

默认使用CPU亲和集合中的最小编号；指定CPU可直接运行`runtime.py --code 01_调度算法源代码 --output 运行结果/runtime --repeat 3 --cpu 8`。共享主机的调度噪声仍可能影响时间，保留逐轮数据而不只给单次最优值。`decision_benchmark.py`用于具有相同输出的两个源码版本对照，不用于本报告的贪心性能比较。

PR17固定提交为`f26313bd67e7640da27635cb3588062a6884911b`。在材料根目录执行：

```bash
git fetch origin f26313bd67e7640da27635cb3588062a6884911b
mkdir -p 运行结果/pr17
git -C ../.. archive f26313bd67e7640da27635cb3588062a6884911b submissions/dpj | tar -x -C 运行结果/pr17
python3 run.py extended --data 运行结果/pr17/submissions/dpj/data --repeat 3
```
