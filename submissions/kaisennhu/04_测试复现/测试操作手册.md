# 构建与复现

完整克隆仓库后，在`submissions/kaisennhu`执行。环境为Linux或WSL，需C++17编译器、make、nm（binutils）、Python 3.10+；规模测试另用`/usr/bin/time`。基础运行不依赖第三方Python包、GPU或网络。

## 统一入口

| 命令 | 内容 |
| --- | --- |
| `python3 run.py build` | 核验并复制仓库public中的固定SDK，编译唯一策略 |
| `python3 run.py solve --input input.json --result result.json` | 生成计划并由官方validator独立回放 |
| `python3 run.py quick` | 官方自测，以及38功能、74边界、19准入、6评分门禁、8engine检查，27项规划专项，以及策略目标文件依赖检查 |
| `python3 run.py score` | 官方39条，分别评方案与同计量入口的官方贪心 |
| `python3 run.py extended` | 553条输入，各3次运行、回放和输出哈希比较 |
| `python3 run.py compare` | 292条扩展输入，双方各3次成本对照 |
| `python3 run.py scale` | 两类十万请求各一次；三类高iov各三次，记录策略耗时、堆内存、RSS |
| `python3 run.py demo` | 七个场景的贪心/方案对照及回放 |
| `python3 run.py all` | 执行以上完整验证，耗时较长 |

结果写入`运行结果/UTC时间`，可用`--output`指定。`--repeat`调整扩展及规划专项测试次数。辅助扩展对照超时600秒；官方评分仍使用原套件时限。score会拒绝非法结果、缺失输入、策略内存缺失/非法/超限或资源检查失败，不只看评分脚本退出码。

Git仓库只保留源码。如自行生成Linux x86_64静态程序及manifest，可用`solve --prebuilt`；该入口校验策略、SDK及二进制哈希。Windows原生不能运行Linux ELF，需WSL。

| 输入组 | 数量 | 数据来源与角色 |

| official | 39 | 官方原始公开数据，不改字节 |

| admission | 19 | `admission_workloads.py` |

`extended`和`compare`自动按manifest生成缺失的451条输入，并逐字节校验SHA256；63条固定输入保留在Git。高iov输入也由`stress_inputs.py`生成，无需保存大体积JSON。所有生成数据是本地合成负载，不是官方隐藏集。

## 加入新负载

```bash
python3 run.py build
python3 04_测试复现/independent.py --code 03_程序 --output new_inputs --seeds 9401 9413 --submits 40 --per-card 32
python3 run.py extended --data new_inputs --repeat 3
python3 run.py compare --data new_inputs --repeat 3
```

先固定策略与SDK哈希，再生成未见负载。新种子未必代表新分布；扩大验证还应增加家族、资源组合、桶边界、到达变化和热点迁移。保留失败与成本回退，修改参数后重新留出未见数据。

## 结果口径

J是官方模拟成本，不是本机运行秒数。新版`policy_peak_mb`统计策略堆内存；`process_peak_mb`/RSS包含框架，单独报告。策略内部没有局部模拟；外部engine执行和validator不属于策略计算。

SDK原`nds_baseline`入口不输出内存标记，因此`greedy_policy.cpp`直接构造原GreedyBaseline并链接官方player_main，生成`nds_greedy_metered`。`engine_checks.py`验证它与原入口输出一致，并检查真实内存超限、未计量程序拒绝及TTL语义。

文档导出使用`生成方案报告.py`，另需python-docx；导出物供本地阅读，不进入Git。完整证据的源码哈希和逐例结果摘要位于05目录。

规划专项可单独运行：

```bash
python3 04_测试复现/planning_checks.py --code 03_程序 --repeat 3 --output planning_results
```

它保留输入、输出和哈希，覆盖尺寸桶前后、一个IOCB共享单槽位、多所有者排队、跨卡/空洞、中转池满、混合大小、不同调用费及上千片段。`--old-player`可传入冻结的对照二进制；该对照不进入正式策略。

`policy_boundary.py`单独编译策略目标文件，检查其SDK依赖仅包含JSON与对齐辅助函数，拒绝Simulator或Trace读写等依赖。它是构建依赖检查，不是通用安全沙箱。
