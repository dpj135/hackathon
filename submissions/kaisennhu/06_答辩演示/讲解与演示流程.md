# 答辩与现场演示

建议讲解10分钟，演示3分钟。按“问题→流程→具体决策→证据与边界”展开，避免先罗列算法模块。

| 时间 | 内容 | 材料 |
| --- | --- | --- |
| 1分钟 | 输入指定数据与目标，调度器优化完整Trace的时间＋调用成本 | [入门说明](../00_快速入门/方案介绍.md) |
| 2分钟 | 到达时分块、采样组数、选路与DIRECT内部拆分；完成后判断是否缓存 | [算法设计](../02_算法方案/算法设计.md) |
| 3分钟 | SSD从100B开始、5MiB分给两卡：扩读、两种切法、FALLBACK与J=570 | [逐步示例](../02_算法方案/双卡读取逐步示例.md) |
| 2分钟 | 复用频率与证据新鲜度检查，再算净收益与预算；满池仍允许新热点替换 | 算法设计第3节与缓存算例 |
| 2分钟 | 公开成绩、留出回退、内存口径与未知未来 | [验证报告](../05_验证结果/验证报告.md) |

现场运行：

```bash
python3 run.py quick
python3 run.py solve --input 02_算法方案/示例/双卡分配输入.json --result result.json
python3 run.py demo
```

demo比较七类场景：连续小读、热点复用、小池大工作集、小对象、短TTL、热点迁移、稀疏非对齐读取；双方结果都经过官方回放。观察J及时间、调用费、提升和命中，不能只比较命中率。

回答评审时明确三个限制：计数DP只在启动条件满足时启用，copy并发仍需仿真复核；窗口和历史不能保证未来；公开高分不代表每例必胜。最新24条留出组合11条更优、13条更差，最大回退16.38%，应主动展示。

PPTX、PDF、逐页图片和完整运行记录保留在本地交付，Git中只保留这份讲解提纲和可运行演示脚本。
